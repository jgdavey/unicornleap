# AGENTS.md

This file provides guidance to AI coding agents working with code in this repository.

## Overview

`unicornleap` is a macOS command-line tool (Swift 5, macOS 10.15+) that animates a unicorn image leaping across the screen with a sparkle particle trail, using CoreAnimation. There's no man page: `unicornleap -h`, generated from `Command.swift`, documents the options.

## Commands

```sh
make              # swift build -c release, copied to build/unicornleap
make universal    # x86_64 (10.15+) + arm64 (11+) universal binary, as shipped in releases (one swift build per --triple, then lipo), plus completions
make completions  # zsh/bash/fish completion scripts in build/completions, generated by the built binary (`make` does this too)
make test         # swift test (Swift Testing; Command Line Tools are enough, no Xcode)
make images       # copy images/*.png to ~/.unicornleap/ (default image location)
make install      # build if needed, install the binary and completions under $(DESTDIR)$(PREFIX) (default /usr/local)
make clean
swift run unicornleap -- -n 3   # build and run via SwiftPM
```

Run a single test:

```sh
swift test --filter CommandTests/defaults
```

Neither Xcode nor an Xcode project is needed; `Package.swift` defines the SwiftPM package (open it in Xcode if you want the IDE). The Makefile builds the shipped binary through SwiftPM, so the package is the single build definition. The only dependency is swift-argument-parser, pinned in `Package.resolved` (commit it); version 1.8 needs a Swift 6 toolchain. Keep the x86_64 triple in the Makefile in step with `platforms` in `Package.swift` (macOS 10.15, the minimum for Swift Testing).

The default images are embedded in the binary at link time (`-sectcreate __TEXT __unicorn_png|__sparkle_png`, in `Package.swift`'s `linkerSettings`), so the built binary runs with no setup. `~/.unicornleap/unicorn.png` / `sparkle.png` override them if present (`make images` copies the defaults there).

## Architecture

- `main.swift` — top-level script: `parseCommand()` parses the arguments with `Command.parse()`; help goes to stdout with exit 0, and any parse or validation error goes to stderr (with the usage line) with exit 1 — not ArgumentParser's default of 64. Then it prints the version, or the `-v` lines, and calls `leapManyUnicorns`: it loads the images, starts one `CATransaction` per unicorn, staggering each by `seconds / 8`, and drives everything with `CFRunLoopRun()`; the completion block of the last transaction calls `CFRunLoopStop` to exit. Herd mode defaults to 30 unicorns, and `Command.eccentricityForNextLeap()` gives each one a random height.
- `Command.swift` — the CLI, a swift-argument-parser `ParsableCommand`. Each option is declared once there with its help text; `validate()` rejects values the types allow but a leap can't use (non-positive or non-finite seconds, non-finite eccentricity, non-positive number). `-e` uses `parsing: .unconditional` so negative values aren't taken for flags, and `-V` is our own flag (ArgumentParser's built-in version flag has no short form) that skips validation. Once parsed, a `Command` is immutable and its values are valid. Adding a flag means adding a property there.
- `Leap.swift` — per-unicorn setup: a `Leap` (seconds, eccentricity, screen, images) builds a `UnicornImage` and `SparkleImage` from the shared `LeapImages` and adds their layers/animations to the one transparent, click-through, full-screen `FloatingWindow` that `leapManyUnicorns` creates for the whole run.
- `LeapImage.swift` — `PNGImage` loads and decodes a PNG (`load` reads the file, falling back to the embedded section via `getsectiondata` only when the path is the default); `main.swift`'s `loadImages` does this once per run, before connecting to the display, and exits on a bad image. `LeapImage` is the base class that adds a `CAKeyframeAnimation` along a path for a configurable key path.
  - `UnicornImage` builds the Bézier leap path (off-screen bottom-left to off-screen bottom-right, peak height scaled by `eccentricity`) and animates `position` of a `CALayer`.
  - `SparkleImage` configures a `CAEmitterLayer` and animates its `emitterPosition` along the unicorn's path.

## Tests

`CommandTests` covers the `Command.swift` parser (via `Command.parse([...])`); `UnicornImageTests` covers `PNGImage` and the leap path and layer, using PNGs generated in memory (no image files or display needed); `ExitStatusTests` runs the built `unicornleap` binary (next to the test bundle in `.build/`) as a subprocess to check stdout/stderr and exit status (errors go to stderr with exit 1; `-h`/`-V` go to stdout with exit 0); `VersionTests` checks `Version.swift` against `CHANGELOG.md`. Tests use Swift Testing (`import Testing`, `@Test`, `#expect`), not XCTest, because the Command Line Tools ship Swift Testing but not XCTest. `UnicornLeapTests` does `@testable import unicornleap` against the executable target, so new source files need no registration anywhere: SwiftPM picks up everything in `UnicornLeap/`.

## Releases

Pushing a `vX.Y.Z` tag runs `.github/workflows/release.yml`: it creates a draft GitHub release using that version's `CHANGELOG.md` section (via `scripts/changelog-notes`, which fails the release if there's no section), runs the tests, builds with `make universal`, uploads `unicornleap-X.Y.Z-macos-universal.tar.gz` (binary, `completions/` and README) plus a `.sha256`, signs a packslip manifest of the tarball with `jdx/packslip` (described by `release.toml`, whose completion paths must match the tarball's entries exactly) and uploads it as `packslip.sigstore.json`, then publishes the release. To cut one, run `scripts/bump-version X.Y.Z` on a clean tree: it renames `## [Unreleased]` in `CHANGELOG.md` to `## [X.Y.Z] - YYYY-MM-DD`, sets `version` in `UnicornLeap/Version.swift` (a test checks it against the newest changelog section, and the release fails if it doesn't match the tag), runs the tests, commits "Version X.Y.Z" and tags `vX.Y.Z`. It doesn't push; do that yourself with `git push origin main vX.Y.Z`. A tag with anything after `X.Y.Z` (e.g. `v3.0.0.pre`, `v3.0.0-rc.1`) is published as a GitHub prerelease; it still needs its own changelog section. `.github/workflows/ci.yml` builds and tests every branch push and PR.
